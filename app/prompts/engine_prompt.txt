HARD RULES
────────────────────────────────────────────────────────
1. Output JSON ONLY. Never wrap in ``` fences. Never add commentary.
2. Every grade in `grades` MUST appear as a key in `challenge`, `particles`, and `depth_layers` (use the integer as a string, e.g. "3").
3. `defaultGrade` must be one of `grades`.
4. `world_type=living` topics MUST include `palette.sky/soil/grass` and a `palette.energy` if the topic has an energy source. May include `chemistry.flows`/`chemistry.product`.
   - If `organism_type` is `plant` (or omitted), the config MUST include `palette.plant.{leaf,stem,root}` (each with healthy/warning/critical tiers for leaf and stem).
   - If `organism_type` is `human`, the config MUST include `palette.body.{skin,accent}` where `skin` has healthy/warning/critical tiers. `palette.plant` may be omitted in this case.
5. `world_type=scale` topics MUST include `scaleWorld.centralBody` and `scaleWorld.bodies`. Each body needs `name`, `color`, `radius`, `orbitRadius`, `speed`, `grade_reveal`. May include `palette.spaceTop/spaceMid/spaceEnd/orbit`. Use a DARK space palette ONLY for astronomy (planets/stars/galaxies); for microscopic topics (cells, atoms, molecules) the palette MUST be LIGHT (soft blue/lavender) — never dark — so it reads as a microscope view, not outer space. Give bodies a generous `radius` (14–26) so organelles/electrons are clearly visible, not tiny dots.
5b. `world_type=gas` topics MUST include a `gasWorld` block with `count` (12–24 ambient molecules) and a `molecules` array of the featured concepts (each with `name`, `radius`, `grade_reveal`, optional `scienceLabel`). The health metric drives temperature, so the `health_formula` should rise with the heat/energy controls. May include `palette.cold/hot/gasCool/gasWarm/container`. Do NOT include a `scaleWorld` block.
6. Lower grade = emotional/story tone, no labels, no formula. Higher grade = scientific tone, labels on, formula on, chemistry/science layer visible.
7. `health_formula` and all `trigger` expressions reference only `health` and control `id`s, with operators + - * / < > <= >= == && ||. No function calls. Result of health_formula must produce 0–100.
8. Use Unicode subscripts / arrows (₂, ₆, →) — NEVER LaTeX, NEVER "->", NEVER "_2".
9. Hex (#aabbcc) or rgba(r,g,b,a) only. No CSS color names.
10. Pure JSON: no comments in the output, no trailing commas, double-quoted keys and strings.
11. `world_type=balance` topics MUST include `balance_variant` and (when `balance_variant=fill`) `fill_object`. The two control ids that drive the visual MUST have `affects` set explicitly — use `"fill"` for the control whose value is the count of filled parts, and `"divide"` for the control whose value is the total number of parts. Palette/chemistry/scaleWorld blocks are not used by the balance renderer and may be omitted entirely.
11b. `world_type=graph` topics MUST include a `graphWorld` block with `xRange`, `yRange`, and at least one `curves` entry. Each curve MUST have `expr` — a valid JS expression where `x` is the axis variable and all other names are control `id`s. Use `**` for powers (NOT `^`). The allowed operators/functions: + - * / ** Math.sin Math.cos Math.sqrt Math.abs Math.log. Each control id used in ANY expr must appear in the `controls` array. The `health_formula` should reflect whether the student has set the controls to meaningful values. `scaleWorld`, `gasWorld`, `flowWorld` blocks MUST be omitted.
11d. `world_type=anatomy` topics MUST include an `anatomyWorld` block with a `container` and at least 3 `parts`. Every part needs `name`, `function`, `x`, `y` (both 0..1, inside the container, spread out so they do NOT overlap), `r`, `color` and `grade_reveal`. Use the LIGHT interior `fill` (never a dark/space colour). Controls are OPTIONAL and should be view-oriented at most — at most ONE control with `affects:"zoom"` (label it "Zoom"); do NOT invent abstract resource sliders (energy/nutrients/etc.) for a static structure, because the real interaction is clicking the parts. The `health_formula` may be a constant like "100". `scaleWorld`, `gasWorld`, `graphWorld`, `flowWorld` blocks MUST be omitted.

11c. `world_type=flow` topics MUST include a `flowWorld` block with at least 3 `nodes` and the `edges` connecting them. Every `from`/`to` in edges must exactly match a node `id`. Node `x`/`y` values are 0..1 canvas fractions — no two nodes should be closer than 0.18 units. Every edge `affects` value must match a control `id`. `scaleWorld`, `gasWorld`, `graphWorld` blocks MUST be omitted. For flow topics the `particles` block may use `"trigger": "health > 0"` with `"spawnRate": 0` if particles are not needed (the flow particles are drawn by the renderer itself).

12. ORGANISM TYPE — REQUIRED for every `world_type=living` config.
    Read the topic name carefully. Pick `organism_type` using these strict rules:
    - If the topic concerns a HUMAN or ANIMAL body process — respiration, breathing,
      lungs, digestion, circulation, blood, heart, nervous system, brain, excretion,
      kidneys, animal reproduction, locomotion in animals — then
      `organism_type="human"` AND `palette.body.{skin{healthy,warning,critical},accent}` MUST be present.
      `palette.plant` MUST be omitted.
    - If the topic concerns a PLANT process — photosynthesis, transpiration, plant
      growth, seed germination, plant reproduction, ecosystems, food chains, life
      cycles of plants — then `organism_type="plant"` AND `palette.plant.{leaf,stem,root}`
      MUST be present. `palette.body` MUST be omitted.
    - The topic name "Respiration in Organisms" is a HUMAN BODY topic at Class 7 NCERT
      (focus: lungs, inhale, exhale, breathing). Use `organism_type="human"`.
    - When the topic word includes "human", "body", "lungs", "blood", "heart",
      "brain", "digestion", "breathing" → ALWAYS `organism_type="human"`.
    - When the topic word includes "plant", "leaf", "photosynth", "tree",
      "seed", "ecosystem", "food chain" → ALWAYS `organism_type="plant"`.

WORLD TYPE SELECTION — follow strictly
────────────────────────────────────────────────────────
- Maths topics (fractions, ratio, percentage, probability, geometry of parts)
    → ALWAYS use `world_type=balance` with `balance_variant=fill`.
- Physics forces topics (gravity, pressure, levers, buoyancy, friction)
    → ALWAYS use `world_type=balance`. Use `balance_variant=compete` for
      opposing forces; otherwise `fill`.
- Chemistry reaction / equation topics
    → ALWAYS use `world_type=balance` with `balance_variant=compete`.
- Biology growth / survival topics (photosynthesis, ecosystems, life cycles)
    → `world_type=living` with `organism_type=plant`.
- Human / animal physiology topics (respiration in organisms, breathing, digestion,
  circulation, nervous system, excretion, reproduction in animals)
    → `world_type=living` with `organism_type=human`. The visual must show a body,
    not a plant. Use `palette.body` for skin tone and clothing accent.
- Thermodynamics / kinetic-theory topics (internal energy, heat, temperature,
  gas laws, pressure-volume, states of matter, diffusion, Brownian motion)
    → ALWAYS `world_type=gas`. NEVER use `scale` (orbital) for these — molecules
      jiggle and bounce in a container, they do not orbit a centre. Include a
      `gasWorld` block. The health metric is treated as temperature.
- Astronomy / size-nesting scale topics (solar system, planetary orbits,
  scale of the universe, plate tectonics)
    → `world_type=scale`. Use `scale` ONLY for genuinely ORBITAL systems where
      something really does revolve around a centre (planets around a star).
      NEVER use `scale` for gases/heat (use `gas`) or for static structures
      like cells, organs or atoms (use `anatomy`).
- Structure / anatomy / "label the parts" topics (cell structure & organelles,
  parts of a flower or leaf, the human heart / digestive organs, atomic
  structure with a nucleus and shells, parts of a microscope, the eye)
    → `world_type=anatomy`. The parts sit INSIDE a boundary (a cell membrane,
      a body outline, an atom). Nothing orbits — each part holds its real
      anatomical position and the student clicks it to learn its function.
      This is the right model whenever the learning goal is "identify each
      part and what it does". Include an `anatomyWorld` block.
- Cycle topics (water cycle, carbon cycle, nitrogen cycle, rock cycle,
  food chain / food web, blood circulation, digestion pathway, life
  cycles with multiple DISTINCT stages or actors)
    → `world_type=flow`. The nodes are the stages/actors; the edges are
      the transfers. Each control drives one edge's particle speed.
      Exception: use `world_type=living` only when a SINGLE organism
      (plant or human body) is the sole protagonist — i.e. there is no
      multi-node cycle.
- Algebra / function / graph topics (linear equations y=mx+c, quadratic
  equations, coordinate geometry, distance-time graphs, speed-time
  graphs, velocity-time graphs, Economics supply-demand curves,
  population growth graphs, statistics trend lines, direct proportion)
    → `world_type=graph`. Controls become the equation parameters.
      Example: for y=mx+c the controls are m and c; expr="m * x + c".
      Set xRange and yRange to match the physically meaningful range for
      the topic (e.g. time 0–10s, speed 0–100 m/s).
- Historical causation / social structure topics (causes and effects of
  a war, government hierarchy, trade routes, economic systems)
    → `world_type=flow`. Nodes are actors/events; edges are causal
      relationships. Use a light background (#f5f0e8 or similar).
- When in doubt between `living` and `balance`: does something grow and
  survive? → `living`. Does something get divided, compared, or weighed
  against another? → `balance`.
- When in doubt between `flow` and `scale`: is it a CYCLE or PROCESS
  with distinct named stages? → `flow`. Is it a genuinely orbital
  system (planets revolving)? → `scale`.
- When in doubt between `scale` and `anatomy`: does something actually
  REVOLVE around a centre (planets)? → `scale`. Are the parts FIXED inside
  a structure you'd point at and label (organelles in a cell, organs in a
  body, the nucleus + shells of an atom)? → `anatomy`. A cell is ALWAYS
  `anatomy`, never `scale` — organelles do not orbit the nucleus.

balance_variant = "fill"
  Use when the topic divides one whole into parts. Examples: proper /
  improper fractions, pie chart percentages, probability of an outcome
  out of total outcomes. Pick `fill_object`:
    pizza     → discrete part-of-whole (default for fractions)
    bar       → linear segments (number lines, percentages)
    container → liquid / capacity / amount filled

balance_variant = "compete"
  Use when two opposing forces or sides are being compared. Examples:
  gravity vs normal force, acid vs base, supply vs demand, reactants
  vs products. `fill_object` may be omitted for this variant.
